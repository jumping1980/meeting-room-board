# 會議室預約看板

純前端的會議室預約看板原型：3 間會議室 × 30 分鐘一格的日程格狀圖，支援建立、編輯、取消預約，並在同一會議室同一時段重複預約時擋下。沒有登入、沒有後端，資料存在瀏覽器的 localStorage。

## 功能清單

- **日程格狀圖**：3 間會議室（A／B／C）× 每格 30 分鐘，預設營業時段 09:00–18:00。
- **預約管理**：點選空格建立預約；點選既有預約可編輯或取消。取消會跳出 `confirm()` 二次確認，編輯不需確認。
- **必填欄位**：姓名、會議主題、會議室、時段，缺漏不可送出。
- **衝突檢查**：同一會議室、同一天、時段重疊即拒絕，建立與編輯都會檢查。編輯被拒絕時原預約保持不變。緊鄰時段（如 10–12 與 12–14）允許。
- **時間規則**：固定 30 分鐘一格、不可自由輸入起訖、不可跨日；過去時段以斜紋標示且唯讀；今天會顯示現在時間線。
- **日期切換**：前一天／今天／後一天，或用日期選擇器跳轉。
- **當日預約列表**：格狀圖下方依開始時間列出當天預約。
- **匯出 CSV**：匯出目前所選日期的預約（會議室、時段、預約人）。
- **響應式版面**：適用桌機瀏覽器，也可容納手機寬度。

不在範圍內：登入／權限、後端與資料庫、多裝置同步、週期性預約、設備與容量管理、門口大螢幕模式、通知與行事曆串接。詳見 [spec.md](spec.md)。

## 如何開啟使用

不需要安裝或建置。直接用瀏覽器開啟 `index.html` 即可。

部分瀏覽器在 `file://` 下會禁用 localStorage，若預約存不起來，請改用本機靜態伺服器：

```bash
python -m http.server 8765 --directory .
```

再開啟 <http://127.0.0.1:8765/index.html>。

> 資料只存在該瀏覽器的 localStorage：換瀏覽器或清除網站資料就會消失。

營業時段、每格分鐘數與會議室清單都集中在 `index.html` 內的 `CONFIG` 常數，可直接調整。

## 如何執行測試

沒有測試框架，也不需要指令。用瀏覽器開啟 `test.html`，頁面頂部會顯示「通過 N 項／共 M 項」，每個測試列出名稱、預期值、實際值與 ✅／❌。

目前的測試針對 `app.js` 裡的 `findConflict`，涵蓋：完全相同、完全錯開、前後部分重疊、完全包含、緊鄰時段、不同會議室、不同日期、編輯時排除自身。`test.html` 內有一個記憶體版的假 `bookingStore`，不會碰你在 `index.html` 的預約資料。

## 檔案結構

| 檔案 | 說明 |
|---|---|
| `index.html` | 主程式：HTML、CSS 與 JS 內嵌，包含設定常數、`bookingStore`、UI 邏輯 |
| `app.js` | 衝突檢查函式 `findConflict`，以一般 `<script src>` 載入（非 ES module） |
| `test.html` | `findConflict` 的瀏覽器測試頁 |
| `spec.md` | 需求規格與驗收標準 |
| `bugs.md` | 驗收點交與 bug 紀錄 |
| `CLAUDE.md` | 給 Claude Code 的專案指引 |

## 開發須知

- **檔案限制**：僅 `index.html` + `app.js` + `test.html` 三檔，禁止再拆分其他檔案、禁止引入外部框架。
- **資料層抽象化**：所有預約資料存取都必須經過 `bookingStore`（底層為 localStorage），UI 程式碼不得直接碰 localStorage，以便日後換成後端。
- **`app.js` 的相依**：`findConflict` 執行時會用到全域的 `bookingStore`，載入順序上 `app.js` 在 `index.html` 的內嵌腳本之前，但呼叫時才讀取。
- 介面文字與程式註解使用繁體中文。
